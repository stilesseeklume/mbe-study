# USBAR Studio 学习网站升级设计

日期：2026-08-25（rev2：补入考试英语要求调研 + 循证方法校验 + 校准测试/音频循环/限时阅读/高亮修复）
状态：已定稿（用户确认）
前置讨论：brainstorming 五节设计逐节确认；rev2 依据 NCBE 官方资料与 SLA 研究修订

## 1. 背景与目标

现状：51 页中英混排讲义 + 词典/生词本/笔记/高亮 + 双引擎 TTS + Supabase 云同步 + 老师只读面板。整站为**输入型**设计，无任何英语产出练习；生词/笔记只收不复；教师无反馈通道。

学员画像：廖同学，英语六级、学习能力强、中国政法大学优秀毕业生，常出国。英语底子不弱，但**未经校准**——真实阅读速度与产出水平以第 1 周校准测试为准，不预设瓶颈。考试窗口 2027-2028（现行 UBE 格式）。

考试英语要求（NCBE 官方及备考资料核实）：
- MBE 200 题 / 6 小时（两场各 3 小时 100 题），每题约 1.8 分钟，题干约 150-200 词 → 需要 **120-150 wpm 法律文本阅读速度**，且预留选项分析时间。
- 写作占 50%（MEE 30% + MPT 20%）：MEE 30 分钟 400-600 词，评分以法律分析为主、语言清晰度其次。
- 现行 UBE（MBE+MEE+MPT）2027.2 后逐步退场，2028.7 起为 NextGen；2027-2028 考现行格式，训练方向 = MBE 阅读流利度 + IRAC 写作，无偏差。

目标：把网站从"阅读器"升级为"训练场"——语言地基优先，1 小时/天的输入输出闭环，AI 承担全部批改，老师只看过程数据；一切强度参数以校准数据为准自适应。

## 2. 已拍板的设计决策

| 决策点 | 结论 |
|---|---|
| 主线定位 | 语言地基优先；考试输出训练（MBE/IRAC）延后 3-6 个月 |
| 旧流程 | 「每日 5 搭配 + 1 造句 + 人工批改」推翻，不照搬 |
| 批改归属 | 全部 AI 批改；老师只看过程，零人工批改 |
| 时间预算 | 1 小时/天（维持现状） |
| 输出主形态 | 方案 A 复述驱动（凭理解用英文重述规则） |
| 中文呈现 | 彻底按需：默认纯英文，术语点击锚点、段落点击展开 |
| 激励原则 | 鼓励性来自真实进步可见化，不搞虚荣指标 |
| 信任假设 | 中文展开次数记录进面板但不强制锁——过程可见代替过程管控 |
| 学员水平预设 | 不预设"读得懂、调不出"；第 1 周校准测试定强度，数据说话 |
| 方法依据 | 循证校验（SLA 研究）：AI 反馈、产出式复习、chunks、间隔重复均有强证据；补入音频辅助重复阅读（证据最强）与限时阅读 |

## 3. 每日学习流程（1 小时）

打开网站进入**今日队列**（非直接进讲义）：今日读哪页、待复习词数、复述任务数。

0. **校准（仅第 1 周，一次性）**：读一段 MBE 风格文章测真实 wpm → 做一次复述基线（AI 评术语/句式基线分）→ 结果写入 profile，后续强度参数据此自适应（详见 4.9）。
1. **精读（约 30 min）**：纯英文讲义；术语点击出中文锚点；段落中文点击展开；查词法律义项优先；笔记/高亮照旧。每节读完可发起限时重读（详见 4.10）。
2. **听 + 跟读（约 8 min）**：复述前先听该页核心节 TTS 音频（ear-before-eye），随后按"读 → 听着跟读 → 计时重读"音频循环三遍法（详见 4.11）。
3. **复述（约 12 min）**：3 个概念 + 英文提示词（不给原文），每条 2-3 句英文重述；逐条提交，AI 返回术语问题、句式问题、native rewrite。全英文反馈。
4. **复习（5 min）**：语境还原（原句挖空填回）+ 一词一造（AI 判）轮换；SM-2 调度。
5. **完成**：复述做完才算完成本页，侧栏 ✓ 代表输出闭环走完。

## 4. 模块设计

### 4.1 阅读层改造
- course-content.json 不动，纯渲染层改造：中文段落默认隐藏，点击展开。
- 术语中文锚点：点击术语显示中文提示（来自页面 glossary/法律 overlay）。
- 中文展开行为记录次数（进老师面板）。

### 4.2 查词升级
- 法律义项优先：命中本页 glossary / 法律 overlay 时置顶显示并标注"法律语境"，通用 ECDICT 释义退居其次。
- 每次查词自动入复习候选队列（同页同词去重）——查词是最可靠的"遇到困难"信号。

### 4.3 复述任务
- **素材预生成**：一次性 LLM 跑完 51 页，每页 3 个任务（概念名、英文提示词、参考要点、参考答案），存静态 JSON（retell-tasks）。质量：任务必须对应本页核心规则。
- 界面：概念 + 提示词，多行输入框，逐条提交。

### 4.4 AI 批改管线
- 接入：沿用站内 server 代理架构（同 TTS 模式），新增批改端点，API key 不进前端。
- 模型：优先复用 MiniMax 文本模型（与 TTS 同账号），备选 DeepSeek。
- Prompt 输出结构化 JSON：`{ term_issues: [], style_issues: [], rewrite, term_accuracy }`；约束全英文、不聊天、不翻中文。
- 判分维度仅三项：术语准确、句式地道（法律英语）、中式直译。
- 降级：API 失败 → 任务暂存，恢复后补批改，不阻塞学习。
- 成本预估：每天约 3-4 次调用，月成本几元级。

### 4.5 复习队列（三源合一）
- 来源：① 查过的词 ② 主动收藏 ③ AI 纠正过的表达。
- 练习形态（产出式，不做被动词卡）：
  - 语境还原：初次遇到该词的原句挖空填回
  - 一词一造：用该词写一句，AI 判
- 调度：简化 SM-2（答对间隔拉长、答错归零），每天限量 5 分钟。
- 数据项：`{type, source, context_sentence, interval, ease, due_at, streak}`。

### 4.6 学生成长面板（侧栏入口，不弹窗）
- 词汇流转管道：新查 → 复习中 → 已掌握。
- 复述质量曲线：术语准确率周趋势（自己的曲线）。
- **阅读速度曲线**：限时重读 wpm 历史，标注 120-150 wpm 考试目标区间；音频循环"第一遍 vs 第三遍"提速对比。
- **法律英语兵器库**：AI 纠正过的 native 表达自动收藏为战利品（把纠错重构为捡装备）。
- 成就徽章（法律梗命名）：Motion Granted（首次复述）、Sustained（连续 7 天）、Case Closed（第 10 页闭环）、Habeas Corpus（10 词毕业出队）、Certiorari Granted（术语准确率首次 100%）、**Lead Foot**（wpm 首次破 130）。
- 连续天数温和展示：断签不惩罚、不焦虑提醒。

### 4.7 老师过程面板升级
- 新增"输出质量"区：学生复述原文与 AI rewrite 并排对照（最新 N 条）、术语准确率周趋势、查词重复率（同词反复查 = 未习得）、中文展开次数。
- 新增"校准与速度"区：校准档案（wpm、复述基线、词汇覆盖）+ wpm 周曲线，对照考试目标区间。
- 不展示学习时长类虚荣指标。
- 保留现有：完成数、学习动态、笔记、生词。

### 4.8 完成页绑定
- "完成本页"变为自动判定：3 个复述任务全部提交并批改完成才算完成。

### 4.9 校准测试（第 1 周一次性，强度自适应的基准）
- **目的**：不预设她的水平，用数据定训练强度。校准结果进 profile（study_state `profile` key），老师面板可见。
- **三项内容**（总计约 20 分钟）：
  1. **限时阅读测速**：读一篇 MBE 风格文章（约 300 词，选自讲义 Constitutional Law 章节），计时开始到点"读完"，算出真实 wpm + 3 道理解题验证不是扫读。
  2. **复述基线**：就刚读文章做 1 次复述，AI 按标准管线评分（术语/句式/直译），得基线分。
  3. **词汇覆盖抽查**：从讲义高频法律词抽 20 个，多义术语选法律义项（consideration → 对价），测法律义项掌握率。
- **自适应规则**（示例，写进 profile）：
  - wpm < 100：精读阶段加音频循环比重，限时重读从每节 1 次起
  - 100 ≤ wpm < 130：标准配置
  - wpm ≥ 130：限时重读可跳过，复习队列日限可上调
  - 复述基线分高（术语准确 ≥ 80%）：复述任务可从 3 条减至 2 条、难度上探（含 counterargument）
- 校准 4 周后可重测一次，校准 profile 更新。

### 4.10 限时阅读模块（对齐 MBE 1.8 分钟/题的物理约束）
- **形态**：每节精读结束后可选"计时重读"——点开始，原文重排为无中文、无笔记标记的"净读模式"，读到底点结束，显示本节 wpm 与历史曲线。
- **目标锚点**：120-150 wpm（MBE 要求），曲线进学生成长面板与老师面板。
- **防作弊扫读**：随机 1 题理解题（从该节内容自动生成，静态 JSON）。
- **数据**：`reading_log: [{page, section, words, seconds, wpm, date}]`；study_events kind `reading`。
- 不强制：wpm 达标后模块变为可选。

### 4.11 音频循环三遍法（audio-assisted repeated reading，阅读流利度证据最强方法）
- **流程**（每页核心节，约 8 分钟）：
  1. 第一遍：正常精读（已在精读阶段完成）
  2. 第二遍：**听音频 + 眼睛跟逐词高亮走**（被动跟读，校准耳朵对法律英语节奏）
  3. 第三遍：**计时重读**（同 4.10 净读模式，测 wpm 对比第一遍）
- **依赖**：TTS 逐词高亮（4.12 修复后时间戳驱动）。
- **记录**：三遍的 wpm 对比进成长面板（"第一遍 vs 第三遍提速"是最直观的流利度成长证据）。
- 复用现有 MiniMax + Kokoro 双引擎，零新增后端。

### 4.12 TTS 逐词高亮同步修复（既有 bug，随本次升级一并处理）
- **现状 bug**：前端 `beginWordHighlight` 未使用 MiniMax 返回的逐词时间戳（`payload.data.subtitles`），用匀速插值（进度 × 总词数），语音停顿/长词导致中段漂移；且音频 blob 缓存未存时间戳，重播永远退回插值。
- **修复**：
  1. 解析 `subtitles` 逐词时间戳，构建 时间→词索引 映射，`timeupdate` 时二分查找当前词。
  2. 时间戳缺失（Kokoro 离线引擎/旧缓存）时回退现有插值方案。
  3. 音频缓存结构升级：`{blob, wordTimestamps}`，旧缓存自动失效重建。

## 5. 技术架构

- 纯静态站 + Supabase 不变；批改经 server 代理端点调用 LLM。
- 数据存储：复述记录、复习队列、查词记录、成长统计、校准档案、阅读记录作为 study_state 新 key（`retell_log`、`review_queue`、`lookup_log`、`badges`、`profile`、`reading_log`）；study_events 新增 kind：`retell`/`review`/`reading`/`calibration`。schema 小幅扩展，不改现有表结构。
- 新增文件：`retell-tasks.json`（预生成素材）、批改端点（server）、学生成长面板 `progress.html`（与 teacher.html 对称的独立页，入口在学习室侧栏）、校准流程（welcome 进入态内嵌）。
- 今日队列：welcome 进入态升级（非独立新页），展示今日读哪页、待复习词数、复述任务数、（首周）校准入口。
- 新增数据 key 汇总：`profile`（校准档案 + 自适应参数）、`reading_log`（限时阅读历史）。

## 6. 明确不做

- 苏格拉底多轮对话（成本高、AI 翻车毁体验）。
- MBE 选择题 / IRAC 写作模块（延后 3-6 个月二期）。
- 手机 App / 打包壳。
- 学习时长统计与展示。

## 7. 成功标准

- 校准侧：第 1 周完成三项校准，profile 生效；4 周后重测 wpm 有可测提升（目标向 120-150 wpm 逼近）。
- 学生侧：复述任务日均完成 3 条；复习队列每日 5 分钟内完成；兵器库持续积累。
- 质量侧：术语准确率周曲线上升；查词重复率下降（同一词不再反复查）；限时重读 wpm 周曲线上升。
- 老师侧：面板 30 秒内看清当日学习质量，零人工批改。
